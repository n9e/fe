# Jira 配置指南

告警触发时在 Jira 项目里建一张工单，恢复时在同一张单上评论并自动关闭。同一条告警未恢复期间只会有一张工单，重复通知不会重复建单。

## 前置条件

- 一个 Jira Cloud 站点（地址形如 `https://your-domain.atlassian.net`）
- 夜莺能访问该站点；使用带权限范围的令牌时还要能访问 `api.atlassian.com`

## 配置步骤

### 1. 创建服务账号和令牌（推荐）

1. 打开 admin.atlassian.com → **目录** → **服务账户**，创建服务账号，给 Jira 分配 **User** 角色
2. 在服务账号详情页的 **Credentials** 里创建 **API Token**，授予 `read:jira-work` 和 `write:jira-work`（`read:jira-user` 可选，只用来显示账号名）
3. 复制令牌（只显示一次），并在详情页记下服务账号的邮箱（形如 `xxx@serviceaccount.atlassian.com`）

也可以用个人账号：在 https://id.atlassian.com/manage-profile/security/api-tokens 创建令牌。Jira Cloud 的 API Token 最长有效期 1 年，到期后通知会失败，请留意更换。

### 2. 填写通知媒介

| 字段 | 说明 |
|---|---|
| 站点地址 | 浏览器里打开 Jira 的地址，不要带 `/rest/api` |
| 令牌类型 | 服务账号的令牌、或点 **Create API token with scopes** 创建的令牌选「带权限范围的 API Token」；点 **Create API token** 创建的选「普通 API Token」 |
| 邮箱 / API Token | 令牌所属账号的邮箱和令牌 |
| Cloud ID | 一般留空，夜莺会根据站点地址自动获取 |

填完点 **校验凭证**，逐项查看凭证、账号、部署类型和权限是否满足。缺少的权限以校验结果为准。

### 3. 在通知规则里选择项目

在通知规则里选择这个媒介，然后：

- **项目**、**工作类型**：下拉选择，从项目已有的工作类型里选即可，无需新建
- **恢复时**：默认「关闭工单」，即评论并自动流转到「完成」状态，不需要填写动作名称
- **高级**：关闭动作名称、重复通知时追加评论、优先级映射、标签、自定义字段等，按需配置

同一条告警未恢复期间只有一张工单；工单关闭后同一告警再次触发，会新建一张工单。

规则里的 **测试** 会创建一张真实工单，并默认连恢复一起测。

## 常见问题

- **401**：确认填的是邮箱而不是用户名、令牌没有过期，以及「令牌类型」与令牌本身一致
- **403**：账号在项目里缺少 Browse projects、Create issues、Add comments 或 Transition issues 权限
- **400 + 字段名**：工作类型有必填字段，在规则的「自定义字段」里补上；或该工作类型的界面上没有优先级字段，清空优先级映射
- **评论了但没有关闭**：工作流里没有能直接到「完成」的动作，在规则的「关闭动作名称」里指定一个
