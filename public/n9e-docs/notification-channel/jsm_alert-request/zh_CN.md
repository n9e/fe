# JSM 告警配置指南

把告警发到 Jira Service Management（JSM）的 Operations（原 Opsgenie）：告警触发时在 JSM 里创建一条告警，恢复时自动关闭。同一条告警未恢复期间，重复通知只会让 JSM 里那条告警的次数加一，不会重复创建。系统已内置一个名为 JSM Alert 的媒介，一般无需新建。

## 创建 API 集成

1. 打开 JSM，进入要接收告警的团队（Teams → 团队 → Operations）
2. 左侧选择 **Integrations** → **Add integration**，搜索并选择 **API**
3. 填一个名字（如 Nightingale）并保存，复制页面上的 **API Key**，确认集成处于开启状态

一个 API 集成属于一个团队，key 决定告警发给谁，所以 key 填在通知规则里：同一个 JSM 媒介可以发给任意多个团队。

## 在通知规则里填写

| 字段 | 说明 |
|---|---|
| API Key | 上一步复制的 key。它本身就是凭证，通知记录里会掩码显示 |
| 名称 | 给这个 key 起个好认的名字（如团队名），其他规则可以通过「复用填过的 key」直接选用 |
| 级别与优先级 | 夜莺告警级别对应的 JSM 优先级，默认 S1→P1、S2→P2、S3→P3 |

告警标题取消息模板的 `title`（最多 130 字符），描述取 `content`；告警标签写入 JSM 的 tags，标签和注解写入 details。

## 媒介里的设置（可选）

API 地址默认 `https://api.atlassian.com`，一般不用改；访问 Atlassian 需要代理时，在高级设置里填写代理。

## 常见问题

- **401 / 403**：API Key 不对，或者集成被关闭了
- **422**：JSM 拒绝了某个字段，报错里会写明字段名
- **测试发送**：会等 JSM 处理完再返回结果，成功时显示告警 ID；默认连恢复一起测，即建完再关闭
